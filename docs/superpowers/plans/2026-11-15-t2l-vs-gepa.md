# T2L vs GEPA Head-to-Head Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a harness that measures T2L-best against GEPA-best on Gemma-2-2B-it over GSM8K (and optionally ARC-Challenge), reporting accuracy with confidence intervals plus the cost of each adaptation path.

**Architecture:** One shared evaluation core (loaders, splits, one answer parser, one scorer, result records with a run fingerprint) sits under thin arms. All generation goes through a single vLLM OpenAI-compatible server on GPU 6 that exposes the base model and the T2L-generated LoRA as two model names; GEPA's reflection LM is a second vLLM server on GPU 7. GEPA is integrated as an adapter over the `gepa` package, not vendored logic. Analysis is a separate pure-Python step over `results/*.jsonl`.

**Tech Stack:** Python 3.10, `uv`, pytest, pandas/pyarrow for data, `datasets` for GSM8K/ARC, vLLM (OpenAI-compatible HTTP), `peft`/T2L vendor code, `gepa`.

**Spec:** `docs/superpowers/specs/2026-11-15-t2l-vs-gepa-design.md`

## Global Constraints

- Target model: `google/gemma-2-2b-it`. T2L checkpoint: `SakanaAI/text-to-lora` → `trained_t2l/gemma_2b_t2l`.
- Reflection LM: `Qwen/Qwen3-14B-Instruct-AWQ` served locally; fallback `Qwen/Qwen3-8B-Instruct-AWQ`.
- GPUs: target server on device 6, reflection server on device 7. Never more than one process per GPU. No tensor parallelism.
- Benchmarks: GSM8K test = 1,319 items; ARC-Challenge test = 1,172 items. GEPA uses GSM8K train: D_train n=150, D_pareto n=300.
- Decoding: greedy (temperature 0) for every reported accuracy number; temperature 0.6, top_p 0.95 for GEPA rollouts only.
- GEPA budget: exactly 1,500 metric calls per run; 3 seeds. Greedy arms: 1 run + bootstrap 95% CI.
- Phase 1 gate tolerance: ±6 pp on the 300-item smoke run; ±3 pp on the full 1,319-item run, checked for both `base` (55.27) and `t2l_icl` (56.89).
- Split hygiene: no test item may ever be passed to any optimizer or feedback function. Enforced in code, not by convention.
- Every result record carries: `arm, task, seed, n, score, model_id, adapter, decode, git_sha, vllm_version, torch_version, wall_seconds, generated_tokens, metric_calls, reflection_calls`.
- Metric calls counted on the *metric* boundary, not the HTTP boundary.

## Review Focus

- **GSM8K answer forms**: `#### 18`, `#### 1,200`, `#### -3.5`, answers inside LaTeX or trailing period. Parser must take the last `####` value, strip `$,` and trailing periods, and compare as decimal; the expected behavior is defined by Task 3's tests.
- **Empty or truncated generations**: vLLM may return `""` or a cut-off answer. Must score as incorrect and be recorded, never raise and never silently retried into a different sample.
- **GEPA budget overshoot**: a candidate evaluation that would exceed 1,500 metric calls must be refused *before* issuing the call; the run must end at exactly 1,500 with a recorded curve.
- **Silent adapter fallback**: a request to `t2l_gsm8k` when the LoRA is not loaded must fail loudly. Falling back to base would fabricate a result that looks like T2L.
- **Train/test leakage**: any test-split id appearing in D_train or D_pareto must abort the run before inference starts.
